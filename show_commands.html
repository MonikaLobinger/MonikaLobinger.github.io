git

  • History anzeigen: git log --oneline [-6 nur die letzten 6]

Änderungen rückgängig machen

  • falls nicht gestaged, löscht Änderungen in der Datei:
    • git checkout [--] dateiname (das -- verhindert, daß dateiname als Branch interpretiert wird)
  • eine Datei nur aus dem Stage entfernen
    • git restore --staged dateiname - läßt die Datei auf der Festplatte wie sie ist, entfernt sie aus dem Stage
      • ist das gleiche wie git reset HEAD dateiname
  • alle Dateien nur aus dem Stage entfernen
    • git reset // Das leert den Stage, läßt die Dateien unverändert
  • alle Dateien auf den letzten Commit zurücksetzen
    • git reset --hard HEAD // Das verändert die Dateien auf der Festplatte - neu erstellte Dateien werden nicht gelöscht

Letzten Commit verändern

  • rückgängig machen
    • Rückgängig machen, aber alles im Staging Bereich lassen: git reset --soft HEAD~1
    • Rückgängig machen, Staging index leeren, Dateien aber behalten: git reset HEAD~1
    • Rückgängig machen und alle Änderungen dauerhaft löschen: git reset --hard HEAD~1
    • Eine Datei rückgängig machen: git checkout dateiname
  • Dateien hinzufügen/löschen
    • git add --all
    • git commit --amend --no-edit

Branching

  • Neuer Branch und dahin wechseln: git checkout -b neuerbranchname
  • Zu existierendem Brachn wechseln: git checkout branchname
  • Zu main wechseln: git checkout main
  • Mergen: in MAIN git merge branchname
  • Fertig gearbeiteten und gemergten Branch löschen: git branch -d alterbranch
  • Den aktuellen Branchnamen anzeigen: git branch --show-current
  • Die Änderungen von main in den Branch integrieren : git merge main (wenn der Branch ausgecheckt ist)

Stashen

Stashen ist nötig um zwischen Branches wechseln zu können ohne einzuchecken

  • git stash -u push // Speichert Änderungen (staged und unstaged) und setzt Dateien zurück
    • Das -u ist nur nötig, falls neue Dateien erstellt wurden
  • git stash pop // Holt die Änderungen zurück und löscht den stash
  • git stash list // zeigt alle stashes an
  • git stash show // fasst die Änderungen des letzten stashes zusammen

Repository umbenennen

  • in github
    • Auf der Repository Seite den Reiter "Settings" wählen
    • Oben "rename"
  • im lokalen Repository
    • git remote set-url origin NEW_URL (z.B. git@github.com:MonikaLobinger/poty.git)

lokales Repository nach Github

  • in github neues völlig leeres Repository erstellen
  • Die ssh url mit Ctlr-C in die Zwischenablage kopieren, URL genannt
  • In einer bash in das Verzeichnis des lokalen git repositories gehen
  • git remote add origin URL
  • Beim ersten push danach: git push -u origin main
  • Dann sollte git push funktionieren

Allgemeine Tags

@module

Syntax: @module [<type>] <moduleName>

Markiert die aktuelle Datei als eigenes Modul. Alle Symbole darin werden diesem Modul zugeordnet, wenn nicht anders angegeben.

Man linkt zu einem Modul (z.B. in @link oder @see) mit Doppelpunkt, z.B. wird auf "@module foo/bar" verwiesen, indem man "{@link module:foo/bar}" oder "@see module:myModule" schreibt.

@namespace
/**
 * This is a namespace that contains documentation elements belonging to the Pets
 * domain.
 *
 * @namespace Pets
 */

/**
 * This namespace and the one below represent a more complex hierarchy of namespaces.
 * You can use dots in your namespace names to represent it. I represent functions,
 * classes, and other definitions that belong to domain of promotion types.
 *
 * @namespace Promotions.Types
 */
 
 /**
 * I'm a partner of the namespace above me. I contain functions and classes and other
 * things that belong to promotion filters.
 *
 * @namespace Promotions.Filters
 */
@memberOf
/**
 * @memberOf Pets
 */
@typedef

Syntax: @typedef {typeDesc} typedefName

/**
 * Hi! I'm a reusable type definition. I represent an object, I'm a member of the "Pets"
 * namespace and my actual name is Pets.Pet. You can reference me as the type of tags like
 * @param, for example <code>@param {Pets.Pet} pet - This is a pet</code>. Or, I can be
 * type of object returned by a function; in that case you will see me showing up like this:
 * <code>@returns {Pets.Pet} If everything goes fine, this function returns a new pet.</code>
 * 
 * @typedef {object} Pets.Pet
 * @memberOf Pets
 * @property {string} name - The name of the pet.
 * @property {Pets.PetTypes} type - Is it a dog?
 * @property {Pets.PetBreeds} breed - Which breed of dog or cat is it?
 * @property {string} dateOfBirth - Date of birth of the pet.
 * @property {boolean} [neutered] - Whether the pet is neutered or not.
 */
@callback

Syntax: @callback callbackName

Wie ein @typedef, nur daß der Type immer function ist

Es gibt auch Klassenspezifische Callbacks.

Man kann auch komplexere Typen definieren, z.B. Objekte mit Properties

Tags für Funktionen, ...

@param

Syntax: @param {typeDesc} paramName - Description

Optionaler Parameter Syntax: @param {typeDesc} [paramName] - Description

Optionaler Parameter mit Default Wert Syntax: @param {typeDesc} [paramName=Der Default Wert] - Description
